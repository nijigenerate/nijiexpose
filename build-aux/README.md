# Native application packages

These are the active C++ distribution assets.
D-specific resource files, WiX projects, dub scripts and Flatpak recipes remain
archived and are not used by this build.

Build the application first, following [native/README.md](../native/README.md).
Install GNU gettext tools (`msgfmt`, `xgettext`, `msgmerge`) for translation
maintenance. Windows CI compiles the catalogs in its Linux translation job and
passes them through `out/i18n` when host `msgfmt` is unavailable. Configuration
fails if neither a compiler nor the required compiled catalogs is present.

```sh
cmake --build build/native-release --config Release --parallel 3
cpack --config build/native-release/CPackConfig.cmake -C Release
```

Outputs are in `build/native-release/packages`:

| Platform | Architecture | Formats |
| --- | --- | --- |
| Windows | x64 | ZIP, MSI (WiX 3) |
| macOS | arm64 | ZIP containing `.app`, DMG |
| Linux | x86_64 | ZIP, AppImage |

On Windows, run `./build-aux/windows/ensure-wix.ps1` before CPack. It uses the
installed WiX binaries, downloading the pinned binary package only if absent.
The MSI keeps the archived installer's upgrade identity. Application versions and
archive names use the exact Git tag, or the nearest tag plus `-g` and a 12-digit
commit ID (only the commit ID when no tag exists). Numeric installer metadata
uses the tag's `MAJOR.MINOR.PATCH`, falling back to `0.0.0` for nonnumeric tags.
An installed MSI with a higher numeric version must be removed before installing
a lower one; commit IDs do not participate in MSI upgrade ordering.
No installer is run by the package checks.

The macOS app includes its icon, INP document registration, camera permission
description, dylibs, tracker models, translations and license notices. CMake
fixes bundled library paths and ad-hoc signs the completed app. This is not an
Apple Developer ID signature or notarization. The supported macOS minimum is
recorded from the SDK used by the existing tracker build. Intel/universal
packages are not generated by the arm64 tracker recipe.

Linux archives retain `bin`, `lib` and `share` together. They include SDL3 and
the embedded tracker, fonts, icons, desktop/AppStream metadata, translations
and models. They target Ubuntu 24.04 x86_64 or a compatible system and use its
runtime libraries: `libfreetype6`, `libxtst6`, `libx11-6`,
`libgl1`, `libstdc++6` and their dependencies. File dialogs require a desktop
portal or the platform dialog support described in the native build guide.
Launch `bin/nijiexpose`; for system integration install the same tree
with `cmake --install <build> --prefix /usr/local`.

CI builds and packages all three platforms, checks the unpacked ZIP's runtime,
model hashes, gettext catalogs and licenses, and runs the packaged executable's
`--version`. Windows also runs the existing native test suite. Application
compilation uses sccache; source-built MediaPipe uses a persisted Bazel action
cache keyed by platform, compiler/SDK and recipe. These are compiler caches,
not externally supplied locally built SDK binaries.
On Unix, the sccache directory and Bazel cache are saved separately before
packaging, including after build failures, so packaging errors do not discard
completed compilation work.

To check an unpacked archive locally:

```sh
python3 native/tools/verify-package.py <unpacked-package-root>
```

Linux Lua 5.1 is statically linked using the distribution archive. Generate the
AppImage with `python3 build-aux/linux/appimage.py <build-directory>`.
Unlike the ZIP, it bundles the runtime libraries selected by linuxdeploy and
their package notices. The resulting image is extracted and launched for verification.
File dialogs use the host's XDG Desktop Portal (including its desktop-specific
backend). Zenity, GTK and portal services are not bundled; the AppImage build
rejects those components if they enter the package. Do not enable a GTK
linuxdeploy plugin for file dialogs. SDL's driver selection is not overridden
by the launcher. On WSLg, the application temporarily prefers system Zenity
when installed, unless the user explicitly selects another SDL dialog driver.
CPack can still produce a tar.gz locally, but CI release distribution uses AppImage.

Nightly publishes ZIP files and a macOS DMG; version tags publish MSI/DMG/AppImage
after all platform checks pass. Beta and RC tags create prereleases. Manual
`nightly` and `release` modes also publish; `verify` only saves Actions artifacts. See [release triggers](../BUILD.md#nightly-and-tagged-releases).
